# Phased implementation plan

1. **Foundation (in progress):** database-backed accounts and sessions, local password recovery with durable, bounded mail retries, self-service and administrator account deactivation, self-reported profiles with separate patient profile consent, public authentication rate limits, explicit admin clinician verification, patient relationships, scoped consent, care team messaging, durable in-app workflow notifications, a patient-facing subset of clinician access activity, basic private uploads, audit events and connected browser forms. Email ownership verification does not gate sign-in. Mail defaults to the local catcher; explicitly configured SMTP uses authenticated TLS, but provider delivery and production deployment require assessment. Add account reactivation policy, verified organization membership, pagination and external notification delivery, and additional security controls.
2. **Persistence and jobs:** extend SQLAlchemy/PostgreSQL models and Alembic migrations for clinical records and processing; extend Redis/Celery job monitoring; document and knowledge import dispatch use a transactional outbox and bounded recovery for expired worker claims.
3. **Documents (in progress):** Native PDF text, configurable local OCR and bounded DOCX body-text extraction run in a worker with page or logical-segment attribution. An optional full-page mode retains supplemental OCR separately from native text. A PDF/image page preview is displayed alongside labeled-field transcription, with a versioned schema and doctor-review history. Earlier processing runs and their saved unverified summaries remain accessible read-only through a refreshable, paginated history; only the latest completed run can be reviewed or used to generate a new summary. An explicitly requested unverified document summary cites bounded source sections. Optional patient-requested vision transcription stores a separate unverified layer for up to three pages. Patient-requested deletion removes extracted data and queues local original-file removal while retaining referenced notes and conversations. Opt-in S3 uploads use durable intents, session-checked association, patient-initiated conservative recovery and discard, ongoing verified reconciliation of discarded objects, and age-delayed cleanup of unlocked files in a dedicated staging directory; authorized download, preview, and worker processing read version-addressed objects. Linked object deletions remove the recorded version and verify that the exact key has no remaining versions or markers; provider failures remain pending. Add bounded retention and scalable reconciliation for discarded intents, automatic orphan discovery, persisted storage locations and migration, private S3 integration, retention policy, backup deletion, mandatory scanner deployment and rescanning, stronger sandboxing, fuller DOCX coverage and visual preview, additional OCR and VLM providers, broader model evaluation, general structured extraction, and field-level bounding boxes.
4. **Clinical review (in progress):** consent-scoped consultation history and stable note links, clinician note versions with draft/pending/approved/rejected/superseded states, rejection reasons and line comparisons exist. The note review policy can optionally require a different authorized doctor. A note can retain an optional document-processing run, exact transcription version and selected field references across note versions; a clinician can associate a unique exact note quotation with a field. Add richer evidence relationships, extracted-document corrections, and stronger concurrency coverage.
5. **Knowledge/RAG (in progress):** administrator-managed text and separately staged PDF/DOCX references, approval, source versions, pgvector indexing and filtering are implemented with an optional Ollama embedding provider. Staged imports can be explicitly retried after parsing failures or deleted with retrying local file removal. An optional policy requires a different administrator to approve each source. Administrators can assign verified doctors for clinical recommendations, with an optional approval gate requiring the latest recommendation. Background indexing uses durable database dispatch and fenced worker claims; the synchronous API remains available for compatibility. Add an automatic retention policy, specialty-aware clinical governance, immutable model identity, and stronger assistant integration.
6. **Assistant (in progress):** private patient-scoped conversations, one-use WebSocket tickets, per-turn consent checks, selected evidence, optional Ollama output and safety checks, opt-in account-scoped response-style preference, and clinician-written or AI-assisted note drafts referencing cited patient-context responses are implemented. Draft generation supports retry keys and fenced claims. Add robust model evaluation, stronger safety controls, and richer tools.
7. **MCP and operations (in progress):** Local stdio tools expose documents, patient profile, consultation history, and approved knowledge through scoped, patient-bound, revocable credentials and consent-checked application APIs, with integration rate limits. Administrators can page through bounded audit metadata and view aggregate document-job states; readiness checks database and Redis. HTTP and WebSocket audit events use connection/request correlation IDs; bounded API response, latency, and provider-failure counters are process-local. Add standards-compliant OAuth for any future HTTP MCP deployment, broader rate limits, distributed tracing and aggregated metrics, audit export, backups, secure production configuration, broader accessibility and browser coverage. Synthetic Vitest and Playwright tests cover core patient and clinician flows, including a cited transcription field remaining tied to an older review after a later correction, plus selected automated accessibility checks.

Labeled-field transcription stops associating later fields with an item when intervening unrecognized text makes the association uncertain; review the original for omitted fields.

The product must not claim clinical safety, regulatory compliance, or production readiness until independent clinical, security, privacy, and legal assessments are complete.
